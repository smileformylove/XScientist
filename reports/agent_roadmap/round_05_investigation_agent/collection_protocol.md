# 授权真实调查任务集采集与冻结协议

## 1. 适用范围

本协议只用于经授权的真实任务或不可逆脱敏后的真实任务。任务标签用于评测线索检索和
证据组织，不用于输出身份、责任或案件结论。未经书面授权、授权范围过期、媒体清单与
授权不一致的任务不得进入数据集。

## 2. 角色隔离

- 数据管理员：核验授权、生成媒体 manifest、管理原始视频访问。
- 主标注员：根据原始媒体和任务记录独立标注证据与不相关证据。
- 复核员：独立检查时间、摄像头、frame、bbox、对象类型和禁止结论。
- 裁决员：只处理主标注与复核分歧，不参与候选 Agent 开发。
- 开发人员：只接触 development 标签；holdout 标签在正式运行结束前保持封存。

大模型可以在系统运行时拆解目标，但不得生成、补齐、改写或裁决评测标签。

## 3. 授权与媒体冻结

1. 为每项任务登记授权引用、用途、审批时间、过期时间和脱敏级别。
2. 把允许访问的 asset、camera 和时间范围写入 scope manifest。
3. 对 manifest、每个媒体文件或受控媒体引用生成 SHA-256。
4. 任务只能引用 manifest 内的视频；越界访问判为权限失败。
5. development 与 holdout 按案件/事件分组切分，禁止同一事件、同一 track 或近重复片段跨分区。

## 4. 人工任务构建

对每项真实任务，人工记录：

- 用户原始调查目标；
- 对象、时间、地点、行为和约束；
- 允许的数据范围；
- 必须找到的关键证据及可回放 source reference；
- 容易混淆但不相关的证据；
- 冲突或反例证据；
- no-match 状态；
- 禁止得出的身份、责任和案件结论；
- 一条或多条可接受工具路由，仅用于评估路由合理性，不规定唯一推理过程。

no-match 任务的 `expected_evidence` 必须为空，停止原因必须为 `no_match`。正任务至少包含
一条人工复核且能回到原始视频的证据。无法回放的条目不得成为期望证据。

## 5. 双人复核与裁决

1. 主标注员和复核员分别查看原始视频，不查看模型输出。
2. 两人核对 asset、camera、起止时间、frame_idx、target_type，以及适用时的 bbox/track。
3. 分歧由裁决员回看原始视频后处理，记录裁决原因。
4. 只有 `adjudication_status=accepted` 且 `llm_generated_labels=false` 的任务可进入评测。
5. 对关键证据做可回放检查；source reference 失效的任务移出数据集并生成新版本，而非静默修补。

## 6. 数据覆盖审计

冻结前统计但不人为从 holdout 反向补题：

- 正任务与 no-match；
- 单摄像头与跨摄像头；
- scene、frame、region、track、entity 所需粒度；
- 单假设、多假设、冲突证据；
- 可用/不可用源视频；
- 对象类型、天气、昼夜、遮挡和低质量分桶（仅在真实元数据存在时）。

缺少某类真实任务时将该分桶标为 Missing，不由大模型生成任务填充。

## 7. 冻结与防泄漏

1. 将逐任务 JSON 按 `investigation_task.schema.json` 校验。
2. 生成有序任务 manifest，记录每个任务 SHA-256、媒体 manifest SHA-256、分区和协议版本。
3. 对整个 manifest 生成 SHA-256；报告必须引用该哈希。
4. development 可用于策略和预算选择；holdout 只运行已冻结代码、配置和阈值。
5. holdout 结果不能用于生成训练样本、hard-negative、提示词或阈值后再重跑同一版本。
6. 任务删除、更正或授权撤销必须产生新数据版本，并保留变更账本。

## 8. 一次查询基线

在候选 Agent 运行前，对同一 task manifest、媒体 scope、权限、模型、索引和缓存策略运行
当前“一次 QuerySpec / 一次检索”流程。每项任务只允许一次初始检索，不进行后续下钻；
仍需记录完整成本和可回放 source reference。基线输出与候选 Agent 使用同一评分器评估。

如果当前仓库没有 QuerySpec 或对应 runtime，则基线状态为 Unavailable，不能使用关键词搜索、
ANN 自召回或人工挑选结果代替。

## 9. 候选 Agent 轨迹

每次执行必须通过 `investigation_trace.schema.json` 校验并记录：

- task、代码、配置、模型和输入 manifest 指纹；
- 假设分支及状态；
- 每次类型化工具调用的输入/输出引用和哈希；
- 每次粒度转换的来源、对象、质量门和模型指纹；
- query-bound 缓存键及命中状态；
- CPU、GPU、视频读取和 wall time；
- 停止原因、最终可回放线索和 Evidence Ledger 哈希。

重复的同工具、同输入哈希调用计为重复调用；跨 query 缓存或无法重放的 final clue 直接判定失败。

## 10. 评测与发布门禁

同一冻结任务集分别计算一次查询基线和候选 Agent 的：任务完成率、关键证据 Recall/Precision、
工具路由正确率、错误对象类型率、无依据陈述率、错误身份合并率、冲突发现率、no-match 正确
停止率、工具调用数、端到端耗时和资源成本。报告绝对耗时以及相对变化，不用单工具加速替代
端到端结果。

以下任一项使候选不能通过：

- 轨迹可重放率低于 100%；
- 存在无法回到原始视频的最终线索；
- 无依据陈述率或错误身份合并率增加；
- 使用越权媒体、未冻结标签或模型生成标签；
- 通过放宽质量门制造表面召回提升。
